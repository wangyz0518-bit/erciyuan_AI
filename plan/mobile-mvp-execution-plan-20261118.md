### 2.1 人物中心产品原则

项目发起人已明确：本产品以人物身份而不是会话作为核心。每个人物只有一条持续存在的逻辑对话时间线；后台自动管理归档和上下文，用户不创建/切换多个会话。不同人物的数据和记忆完全隔离。用户拥有原始记录及派生记忆，必须支持一键导出。

三层模型为：

1. **原始层**：完整、可追溯的互动记录，是事实来源，归档不能删除。
2. **记忆层**：归档片段的摘要和索引，保留原始事件引用；优先检索摘要，需要细节时回查原始记录。
3. **身份层**：人物背景、性格、表达方式、关系和稳定状态，每轮对话加载；区分用户设定与模型归纳，不能静默覆盖用户设定。

“无限上下文”是长期连续的产品体验目标，不是无限 Token。高缓存率通过稳定、版本化的人物身份前缀和动态检索内容后置优化，效果需实测。

详细约束见[人物中心原则文档](../docs/design/person-centered-companion-principles-20261118.md)。

## 3. 已有成果复用原则

### 3.1 复用流程

每项任务开始前，先检查下表对应的已有 PR、变更文件、增量提交、测试、报告、接口契约和许可证：

1. 区分已合并到 main 的代码、未合并 PR 的代码、纯设计/研究材料和本机证据。
2. 对可直接复用的设计和文档，保留来源并在新 Issue/PR 中注明。
3. 对未合并 PR 中的代码，只提取经过审查且属于目标功能的增量；在自己的分支中选择性移植，补齐当前 main 的兼容性与测试。
4. 不整体合并其他作者的分支，不修改或关闭其他作者的 PR，不覆盖其分支和提交。
5. 复用模型、SDK、角色素材或第三方资源前，检查许可证、分发权限、隐私和用户授权。
6. 若已有实现不满足正式产品安全、平台或维护要求，保留其验证价值，明确缺口后再改造；不为“复用”而继承已知缺陷。
