## 3. 已有成果复用原则

### 3.1 复用流程

每项任务开始前，先检查下表对应的已有 PR、变更文件、增量提交、测试、报告、接口契约和许可证：

1. 区分已合并到 main 的代码、未合并 PR 的代码、纯设计/研究材料和本机证据。
2. 对可直接复用的设计和文档，保留来源并在新 Issue/PR 中注明。
3. 对未合并 PR 中的代码，只提取经过审查且属于目标功能的增量；在自己的分支中选择性移植，补齐当前 main 的兼容性与测试。
4. 不整体合并其他作者的分支，不修改或关闭其他作者的 PR，不覆盖其分支和提交。
5. 复用模型、SDK、角色素材或第三方资源前，检查许可证、分发权限、隐私和用户授权。
6. 若已有实现不满足正式产品安全、平台或维护要求，保留其验证价值，明确缺口后再改造；不为“复用”而继承已知缺陷。

### J：ASR/TTS 接入

**依赖**：E、F、I；平台验证按 G/H 条件执行。

**工作范围**
- 结合 PR #18/#19 的语音研究、PR #21/#22 的 TTS 实测、PR #23 的负面实验和 PR #24 的音色管理设计，确定实际可用的 ASR/TTS 方案。
- 实现录音上传/识别/转写编辑确认/发送的 ASR 流程。
- 实现文字转语音、角色音色绑定、播放/停止/重试及失败降级。
- 根据真实听感、延迟、成本、授权和平台覆盖选择供应商；不因实验性能数据自动定案。
- 复用 PR #22 的流式音频协议前，补齐 iOS 与弱网/生产安全验证。
- 复用 PR #24 音色复刻时，补齐多用户授权、资源归属、云端删除和数据生命周期。

**交付/验收**
- ASR 转写由用户确认后才发送；错误识别可编辑。
- TTS 与正确角色绑定；停止/切换角色后迟到音频不会播放。
