# 文档规范

## 目录职责

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `docs/` 根 | 总索引、当前状态、架构 | 具体调研、决策正文 |
| `process/` | 团队安排、协作流程、文档规范 | 技术方案 |
| `research/` | 调研、选型、技术评估 | 最终决定 |
| `decisions/` | 决策、理由、后果 | 调研数据、长篇对比 |
| `guides/` | 配置、开发、排障 | 产品需求 |
| `接口/` | 接口契约草案 | 产品功能描述 |
| `archive/` | 过期或被取代的文档 | 仍在使用的文档 |

`planning/` 保持独立，放阶段计划、Word 文档和生成脚本，不并入 `docs/`。

## 命名

- 目录使用小写英文，单词用连字符分隔。
- 文件名格式：`<主题>-<类型>-<日期>.md`，日期为 `YYYYMMDD`。
- 正文标题使用中文。
- 示例：`mobile-stack-review-20261111.md`。

## 状态头

每份文档开头写：

```markdown
> 状态：草案 / 评审中 / 已定案 / 已废弃
> 日期：2026-11-11
> 负责人：待定
> 关联：A/B/C/D、ADR-0002
```

- 调研报告的状态只能是“草案”或“评审中”，不能写“已定案”。
- 决策记录使用 ADR 的“提议 / 已接受 / 已取代 / 已废弃”。
- 状态变化时更新状态头，不修改历史结论。

## 索引

- 每个子目录必须有 `README.md`，列出本目录文档、用途和状态。
- 新增文档先更新所在目录的 `README.md`，再更新 `docs/README.md`。
- 根 `README.md` 只索引到 `docs/README.md` 和 `planning/README.md`，不逐条列文件。

## 调研与决策分开

- `research/` 记录事实、选项、证据和不同意见，可以有多份，也可以结论冲突。
- `decisions/` 记录最终选择、理由和后果，一个编号一个决定。
- 决策被取代时标为“已取代”，并链接新 ADR，不删除旧文件。
- 调研报告结论变化时新增日期版本，不覆盖原报告。

## 归档

- 过期、被取代或不再维护的文档移到 `docs/archive/`。
- 归档时在索引中注明“已被 ADR-000X 取代”或“仅作历史参考”。
- 不删除有历史价值的调研、决策和验收记录。

## 禁止

- 在调研报告中写“已决定”或把建议当成定案。
- 同一条规则在多个文件重复，应该只保留一处并互相链接。
- 在 README 中堆叠详细规范。
- 直接覆盖他人的 Word 计划或历史文档。
