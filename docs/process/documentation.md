# 文档规范

## 目录职责

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `docs/` 根 | 总索引及按需建立的架构入口 | 具体调研、决策正文 |
| `process/` | 稳定的协作流程、文档规范 | 临时任务安排、技术方案 |
| `research/` | 调研、选型、技术评估 | 最终决定 |
| `decisions/` | 决策、理由、后果 | 调研数据、长篇对比 |
| `guides/` | 配置、开发、排障 | 产品需求 |
| `接口/` | 接口契约及样例 | 产品功能描述 |
| `archive/` | 过期或被取代但有保留价值的文档 | 仍在使用的文档 |

仓库已有 `planning/` 保持独立；其内容不自动构成当前任务计划或协作安排。

## 命名

- 目录使用小写英文，单词用连字符分隔；已有中文目录暂时保留，后续如需迁移应统一更新链接。
- 文件名使用简洁、可辨识的主题名称；调研等有版本时间意义的快照可在文件名中加入 `YYYYMMDD`。
- 正文标题使用中文。

## 状态

需要表达生命周期的文档应在开头标注状态和日期；README、索引及稳定规范不强制添加状态头。

- 设计提案：提议 / 已接受 / 已取代 / 已拒绝。
- ADR：提议 / 已接受 / 已取代 / 已废弃，具体以 `decisions/README.md` 为准。
- 调研：草案 / 评审中 / 已完成；“已完成”表示调研工作完成，不代表建议已被采纳。
- 快照文档保留当时结论，不因后续变化而改写历史；在需要时增加新版本并建立关联。

## 索引

- 每个有独立文档的子目录应有 `README.md`，列出本目录文档及用途。
- 新增文档时先更新所在目录索引，再更新 `docs/README.md`。
- 根 `README.md` 只提供项目入口和关键导航，不堆叠详细文档清单。

## 调研与决策分开

- `research/` 记录事实、选项、证据和不同意见，可以有多份，也可以结论冲突。
- `decisions/` 记录最终选择、理由和后果，一个编号一个决定。
- 决策被取代时标为“已取代”，并链接新 ADR，不删除旧文件。
- 调研结论变化时保留旧快照，必要时新增日期版本，不覆盖历史记录。

## 归档

- 过期、被取代或不再维护但有历史价值的文档，可移到 `docs/archive/`。
- 归档时在索引中注明取代关系或“仅作历史参考”。
- 不为归档而归档；没有历史价值的临时材料不进入正式文档体系。

## 禁止

- 在调研报告中把建议写成已确认决策。
- 同一条规则在多个文件重复维护，应只保留一处并互相链接。
- 在 README 中堆叠详细规范。
- 未经确认覆盖他人的 Word 计划或历史文档。
