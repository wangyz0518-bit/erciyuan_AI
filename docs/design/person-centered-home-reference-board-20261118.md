## 3. 本项目的差异化原则

常见 Agent 以一次会话作为上下文边界，或让多个会话共享全局记忆。本项目采用人物中心模型：

1. 一个用户可以拥有多个不同人物。
2. 每个人物只有一条持续存在的逻辑对话时间线。
3. 人物切换意味着切换到另一个独立人物对象；人物之间的原始记录、记忆和身份状态不共享。
4. 后台自动整理历史：原始记录保留，归档后生成摘要索引，并更新有来源依据的人物身份状态。
5. 每轮对话加载人物身份层，优先检索相关记忆摘要，必要时再展开原始记录。
6. “无限上下文”是长期连续的体验目标，不代表模型 Token 窗口无限。
7. 用户拥有底层数据，必须能一键导出所有人物的原始记录、记忆摘要/索引、人物身份和附件资源。

详细数据结构、归档流程、缓存优化和用户数据所有权约束见[人物中心原则文档](person-centered-companion-principles-20261118.md)。

## 4. A/B 首屏方案

两版使用同一人物、同一组合成消息和同一手机尺寸，区别仅在默认进入路径。

| 维度 | A：人物主页优先 | B：最近对话优先 |
|---|---|---|
| 默认入口 | 先看见当前人物主页 | 直接打开最近使用人物的持续时间线 |
| 首次使用 | 更容易建立人物身份、性格和氛围 | 空状态需要解释人物是谁、如何开始 |
| 回访效率 | 多一次“继续对话”点击 | 少一步，立即看到最近内容 |
| 人物表现 | 大面积人物形象、背景与人设 | 人物身份固定在时间线顶部 |
| 连续性 | 展示上次聊到的内容，再进入同一条时间线 | 直接恢复同一条时间线 |
| 人物切换 | 从人物主页切换到另一人物 | 从聊天头部切换到另一人物 |
| 语音入口 | 主入口放在持续对话页，主页可提供次级提示 | 与持续对话输入区并列 |
| 数据控制 | “我的”提供全人物数据导出入口 | “我的”提供全人物数据导出入口 |
| 主要风险 | 回访多一步；人物主页内容过多会挤压主操作 | 首次使用人物介绍空间较少 |

### A：人物主页优先（当前倾向）

- 人物身份是首页主要内容，而不是一个可替换的 Agent 头像。
- 主操作是“继续与 TA 对话”；首次使用时是“开始认识 TA”。
- 最近内容只作为同一条持续时间线的摘要，不代表一个新会话。
- 适合先让用户认识人物，再建立长期陪伴关系。

### B：最近对话优先（保留对照）

- 打开即进入最近使用人物的同一条持续时间线。
- 人物名称、形象和切换入口固定在顶部。
- 不提供新建会话、会话列表或会话切换。
- 适合高频回访用户，但首次使用时人物身份表达较弱。

## 5. 原型验收边界

- 首次使用、再次打开、继续同一条时间线、切换人物、查看数据管理和导出示例 JSON 均可操作。
- 原型用浏览器本地存储保存合成演示消息；刷新后可恢复，仅用于验证信息结构。
- 导出功能只生成合成演示数据 JSON，不代表正式产品的数据导出实现。
- 三层记忆、自动归档、检索、人物身份自动更新和模型缓存尚未实现。
- 角色形象和消息为原创 CSS 占位及合成文本；语音入口不请求麦克风，不调用 ASR/TTS。
