> 说明：本参考板基于官方 App Store 产品介绍和公开功能描述，不代表已完成逐页安装走查。未复制第三方截图或素材。

## 1. 星野：角色发现与角色资料

- 官方来源：[星野 · App Store](https://apps.apple.com/cn/app/%E6%98%9F%E9%87%8E-%E6%89%80%E5%BB%BA%E7%9A%86%E4%BD%A0%E6%89%80ai/id6463076337)
- 页面介绍：以 AI 智能体社区为核心，支持用户发现角色，并定制形象、声音、人设和技能；产品介绍强调首页推荐与角色创建。
- 可借鉴：
  - 角色卡片不应只有头像和名称，还需要一行人设/陪伴定位。
  - 角色资料应让形象、声音和性格成为同一角色身份的一部分。
- 转化到本项目：
  - 首版只展示少量预置角色，优先让用户理解角色差异。
  - 暂不引入社区信息流、公开创作和分享系统，避免分散本地陪伴主流程。

## 2. 恋与深空：角色视觉与沉浸感

- 官方来源：[恋与深空 · App Store](https://apps.apple.com/cn/app/%E6%81%8B%E4%B8%8E%E6%B7%B1%E7%A9%BA/id1618911882)
- 页面介绍：突出第一人称 3D 剧情、角色互动、日常陪伴和沉浸语音故事。
- 可借鉴：
  - 角色视觉应是页面的主要识别点，而不是被大量工具按钮挤压。
  - 背景氛围、角色状态和互动入口可以共同表达陪伴感。
- 转化到本项目：
  - 用大面积角色展示区建立情绪锚点，但保留清晰的「继续聊天」主按钮。
  - 首版采用轻量占位图/立绘组件，不以高成本 3D、剧情系统或重资源场景作为前置条件。

## 3. Character.AI：聊天恢复与文字/语音切换

- 官方来源：[Character.AI · App Store](https://apps.apple.com/us/app/character-ai-chat-talk-text/id1671705818)
- 页面介绍：强调角色发现与创建，并提供文字聊天、语音交互和角色个性化。
- 可借鉴：
  - 角色身份应在聊天页持续可见，切换角色入口不应隐藏过深。
  - 文字和语音是同一角色会话的不同交互方式，应保持入口关系清晰。
- 转化到本项目：
  - 最近会话入口应尽量减少回访用户的点击次数。
  - 语音入口放在聊天输入区附近，作为文字聊天的补充，不抢占主流程。
  - 首版不做开放社区或复杂角色创建。

## 4. 对本项目的设计约束

- 同一角色、同一组消息、同一手机尺寸比较两种首屏结构。
- 角色展示、继续聊天和切换角色必须清晰；语音入口可见但不喧宾夺主。
- 首次使用与再次打开必须分别设计，不能只展示有历史消息的理想状态。
- 不使用未经授权的第三方角色立绘、Logo 或截图；原型使用原创 CSS 占位形象和合成消息。
- 不把原型的按钮状态描述为真实 AI、录音或语音通话能力。

## 5. 两版方案的取舍

| 维度 | A：角色主页优先 | B：最近会话优先 |
|---|---|---|
| 首次进入 | 先建立角色印象，之后开始对话 | 直接进入角色会话，空状态需引导 |
| 回访效率 | 需要点击「继续聊天」 | 直接看到最近消息 |
| 角色表现 | 角色展示面积大，情绪感强 | 角色以紧凑头像/标题持续出现 |
| 导航 | 主页与聊天是两个明确层级 | 聊天成为默认入口 |
| 语音入口 | 可在角色主页和聊天页分别呈现 | 集中在聊天输入区 |
| 主要风险 | 回访多一步，主流程可能显得较深 | 首次使用的角色介绍空间较少 |

**当前不做最终选择。** 产品计划中的默认入口仍属于待评审问题。建议团队结合首次使用和回访场景共同决定；原型只用于比较结构和交互，不代表正式视觉定稿。
