# ADR-0003 评估常规模型与 AI 辅助素材的 Live2D 制作路线

- 状态：提议（产品方向调整已确认；制作方案待执行和验收）
- 日期：2026-11-13
- 更新：2026-11-14
- 执行状态：当前角色四层素材、Cubism 真实绑定／MOC3 导出、六秒翼尾待机及 Windows Viewer 播放已验证；完整身体动作及 App 自定义模型接入待执行
- 决策者／负责人：方向由项目发起人确认，制作及评审负责人待分配
- 关联：C 形象制作、A 页面装配、B 状态调度、D 声音联动

## 背景与变更记录

产品采用“用户素材与文本 → 服务端制作角色资源包 → App 展示”的三步流程。用户需要自然待机和触发完整动作，不开放任意关节调姿。

2026-11-13 曾提议比较 Live2D 与 AI 视频动作播放器，并已建立技术入口。2026-11-14 用户确认：将第二条路线改为 AI 生成素材再交给 Live2D。旧视频资料与代码作为历史保留，停止将三段 AI 视频作为当前第二方案前提。文件名保留历史路径以免破坏既有链接；当前内容以本次更新为准。

## 当前选项

1. 方案 A：使用现成或常规制作的 Live2D 模型，验证运行模型、动作与 Flutter 接入。
2. 方案 B：AI 生成立绘与分层素材，经过补画、对齐和质量检查，交给 Cubism 做绑定与预设动作，最终导出同种 Live2D 运行资源。

两条路线的 App 渲染端相同，比较重点是自定义角色的素材可用率、制作工时与动作质量。方案 B 不是把几张图片直接变成模型，也不承诺全自动绑定。

## 待执行决定

- 优先执行方案 B 的当前角色最小样本；方案 A 的官方样例作为运行能力基线，不能替代自定义角色验收。
- 依照[新可行性复核与验证流程](../research/avatar-ai-live2d-review-20261114.md)，先验证四层素材、实际 Cubism 导入、简单翼尾参数与待机导出，随后增加协调呼吸、挥手和腿部重心。
- 依照[角色分层任务书](../research/dragon-layer-materials-20261114.md)准备素材，保留生成提示词与修整记录。
- 编辑器安装在 Windows 制作电脑；模拟器运行 App。每步必须有真实结果，不把 PNG、PSD 或程序合成动画标成 MOC3／Live2D 验收。
- 最终交付仍为模型、纹理及动作；沿用 Live2D 包契约方向，具体 Schema 与调用方不由本 ADR 隐式修改。
- 本轮不建设完整上传／生成服务器，不更改首版 Android/iOS 范围。模拟器与真机分别验收。

## 后果及评审条件

AI 生成可以辅助拆分和补画，但必须记录重试、人工修整、绑定及动作制作成本。技术上导入成功不等于画面合格；衣物、翼根、尾根、脸和腿脚都要检查。

最小四层模型只证明制作链路。完整目标仍是自然胸腹与肩部呼吸、完整挥手、可见腿部换重心及回到待机。首轮不要求自由三维视角或精确音素口型。

若素材漂移或补画失败，回到素材阶段，不用硬拼掩盖；若无法完成编辑器安装／导出，应明确阻塞位置。完成真实模型和动作后，再更新执行状态和方案评审结论。
