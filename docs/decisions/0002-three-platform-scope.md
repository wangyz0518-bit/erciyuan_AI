# ADR-0002 三端范围确认

- 状态：已接受
- 日期：2026-11-11
- 确认日期：2026-11-11
- 决策依据：项目发起人确认首版覆盖 Android、iOS，原生鸿蒙后续适配
- 关联任务：[#7 确认三端范围](https://github.com/wangyz0518-bit/erciyuan_AI/issues/7)、[#8 确定移动端首选框架](https://github.com/wangyz0518-bit/erciyuan_AI/issues/8)

## 背景

《手机端框架选型复核与建议（三端需求版）》把 Android、iOS、原生鸿蒙都列为首版目标，并明确“鸿蒙支持”指原生鸿蒙应用，不以安卓 APK 在华为设备上运行为验收依据。

这与 ADR-0001 的前提不同：ADR-0001 把鸿蒙视为未来可能项，主要按 Android/iOS 比较，因此得出 Flutter 优先的结论。

## 选项

1. **三端都做**：Android、iOS、原生鸿蒙同步纳入首版。
   - 优点：一次覆盖主要市场，避免后期返工。
   - 代价：框架选择、构建链、真机验证和人力成本都增加。
2. **Android/iOS 优先，鸿蒙后续**：先把双端跑通，再单独适配鸿蒙。
   - 优点：首版风险低，交付快。
   - 代价：如果架构没有为鸿蒙留余地，后续可能重写 UI 层。
3. **Android 优先**：iOS 和鸿蒙都后置。
   - 优点：最省资源。
   - 代价：与当前产品目标不一致，除非团队明确缩减范围。

## 决定

采用选项 2：**首版覆盖 Android、iOS；原生鸿蒙放到后续阶段适配，具体时间另行确定。**

首版优先完成双端交付，将原生鸿蒙的构建、插件适配和真机验证安排到后续阶段。原生鸿蒙仍是后续适配目标，不属于首版交付或验收条件。

本决策确认首版平台范围。客户端框架另见 [ADR-0001](0001-mobile-stack.md)。两份调研保留各自原始前提和建议，当前平台范围以本决策为准。

## 后果

- 首版 PoC 与验收覆盖 Android、iOS，检查聊天与输入、录音播放、本地记录恢复、形象组件和双端构建安装；按实际结果区分真实能力、模拟结果和未验证项。
- 原生鸿蒙不作为首版 PoC 通过或框架定案的前置条件。后续启动适配时，再评估构建、录音播放、本地存储、形象渲染、包体积和真机性能；安卓 APK 在华为设备上运行不等于原生鸿蒙验证通过。
- 框架选型记录后续鸿蒙适配路径与已知限制；不因本次范围确认宣称任何候选框架已经兼容或通过验证。
- 客户端平台差异集中在适配层，尽量保留统一后台的职责和接口语义；具体接口仍须按接口评审流程确认。
- [ADR-0001](0001-mobile-stack.md) 记录 Flutter + Dart 的客户端选型。双端 PoC 与工程初始化由 [#10 Flutter 双端 PoC 与工程初始化](https://github.com/wangyz0518-bit/erciyuan_AI/issues/10) 跟踪。
