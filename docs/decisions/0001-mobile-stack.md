- 决策者：待定（A/B/C/D 工作线共同确认）
- 相关决策：[ADR-0002 三端范围确认](0002-three-platform-scope.md)（已接受）
- 关联任务：[#8 确定移动端首选框架](https://github.com/wangyz0518-bit/erciyuan_AI/issues/8)

## 背景

项目处于规划阶段，尚无产品代码。第一阶段需要完成手机文字聊天骨架、角色与对话记录恢复，以及形象、声音能力验证。技术栈尚未定案，需要先明确客户端框架，再建立产品代码目录。

约束与偏好：

- 手机优先，Android/iOS 都要覆盖。
- 交互密集：聊天流、录音、播放、角色切换、表情状态。
- 小团队、四条工作线并行，希望减少双端重复开发。
- 关注包体积、流畅度和长期维护稳定性。
- 平台范围已由 ADR-0002 确认：首版覆盖 Android、iOS，原生鸿蒙后续适配，具体时间另行确定。

## 选项

1. **Flutter**：Dart + 自绘引擎，一套 UI 覆盖 Android/iOS/桌面。
2. **React Native + Expo**：TypeScript/React，调用原生控件，生态最大。
3. **KMP + Compose Multiplatform**：共享逻辑与 UI，体积和性能接近原生。
4. **原生双端**：Android Kotlin + Compose，iOS Swift + SwiftUI。

## 评估摘要

详细数据见 [`docs/research/mobile-stack-research-20261111.md`](../research/mobile-stack-research-20261111.md)。相对比较：

| 维度 | Flutter | RN + Expo | KMP + CMP | 原生双端 |
| --- | ---: | ---: | ---: | ---: |
| 双端开发效率 | 5 | 4 | 3 | 2 |
| UI 一致性 | 5 | 3 | 4 | 1 |
| 动画/渲染可控性 | 4 | 3 | 4 | 5 |
| 包体积 | 2 | 3 | 4 | 5 |
| 生态 | 4 | 5 | 2 | 5 |
| 鸿蒙可行性 | 2 | 3 | 1 | 4 |
| 学习成本（分数越高越容易） | 3 | 3 | 2 | 2 |
| 长期维护稳定性 | 4 | 3 | 3 | 5 |

## 当前建议

**基于 Android/iOS 优先的前提，第一阶段优先评估 Flutter**：

> ADR-0002 已确认首版 Android/iOS 的平台范围。本节仍是候选建议，不代表 Flutter 已定案；最终框架由 #8 结合双端 PoC 结果和团队评审确认。

- 一套 UI 覆盖 Android/iOS，适合聊天、语音、形象组件这类交互密集型界面。
- 自绘引擎让动画、滚动和表情切换更可控。
- 官方库整齐，小团队少踩坑。
- 主要代价是包体积和深度系统集成，第一阶段不依赖后者。

**备选 React Native + Expo**：团队 React/TypeScript 基础更强时重点评估，最终选择仍需 PoC 与团队确认。

**暂缓 KMP + CMP**：等业务核心稳定后再评估抽取共享层。

**原生鸿蒙后续适配**：按 ADR-0002 执行，不作为首版交付或验收条件；具体时间与适配方案后续确定。

## 待确认

- 团队成员的技术栈熟练度。
- 形象展示方案（图片/序列帧/Live2D）在候选框架中的性能。
- 包体积预算与目标设备范围。
- 后续原生鸿蒙适配的具体时间、路径和维护成本（不作为首版定案的前置条件）。
- 是否需要桌面端。

## 后果

- 选定后，在 `AGENTS.md` 补充构建、测试、lint 命令。
