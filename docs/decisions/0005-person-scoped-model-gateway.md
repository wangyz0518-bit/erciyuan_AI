# ADR-0005（提议）：人物作用域的可替换模型网关与文字流式协议

- **状态：提议；供设计审查，不代表已批准公网生产架构**
- 日期：2026-11-18
- 范围：#38 模型服务架构建议，#39 文字 API 的实施输入
- 上游：已接受 [ADR-0004 人物中心记忆边界](0004-person-centered-memory-architecture.md)
- 详述：[AI 后端评估](../design/ai-service-backend-architecture-20261118.md)、[文字网关协议](../接口/person-text-gateway-v1-20261118.md)

## 背景

已有 PR #21 提供 FastAPI + DeepSeek/SSE + CosyVoice 本地开发网关，PR #22 提供 WebSocket/PCM 流式语音，PR #24 提供音色任务/绑定。它们的本机令牌、有限角色和全局请求缓存不满足正式多用户安全隔离。新正式工程 #35/#36/#47 已明确 owner+character 是人物事实、归档、检索与身份版本的核心边界。

项目不以模型供应商 session 定义用户聊天；单个人物仅有一条可持续的逻辑时间线。必须在复用原型代码和防止旧会话/单用户设计渗透之间取舍。

## 备选方案

1. **直接部署 #21/#22 旧网关**：代码量最少；但单用户全局 token、固定角色、状态缓存与生产权限不可用，存在隐私/成本风险，拒绝。
2. **完全重新实现一个全新后端**：方便重新规划数据，但重复已验证的传输/provider、重试/取消机制，投入高，暂不选。
3. **以人物作用域封装现有 FastAPI provider/SSE，认证、记忆、请求 ledger 分层**：保留已有实现的可信增量，新建正式权限和上下文接口，后续语音再按需复用 WebSocket/PCM。**推荐。**
4. **全部端侧 LLM**：可能减少网络依赖，但手机算力、功耗、模型质量和跨端适配未经验证，另行研究。

## 推荐方案（待评审）

- 本地 SQLite RawEvent 是事实来源；#47 构建前缀/摘要/来源回查，客户端只发送必要快照，不依赖模型侧 Conversation。
- 文字网关首版采用 HTTP+SSE；Python/FastAPI 和可替换 LLMProvider 端口继承 #21 的供应商流式实现、错误映射和测试，不重用旧全局身份模型。
- 服务端认证主体派生 owner，所有请求、状态、缓存、取消和费用配额键为 owner+character+request_id。客户端自带 owner_id 不能作鉴权。
- 旧 conversation_id 路径仅作为开发 PoC 兼容方案，不出现在正式产品；真实 API 按人物路径组织，而不是“新建会话”。
- 取消/断线不自动重试收费调用；只有完整 completed 回复进入人物原始事实。稳定 identity 前缀与动态上下文分离，后续实测缓存命中率。
- 生产部署、账户提供商、资源保留时间、付费模型预算、客户数据外发需明确授权与安全审查，不由 ADR 自动批准。

## 后果和风险

**收益**：不重造 provider/SSE、保留单人物持续状态、用户数据主权与来源追溯；网关可替换 DeepSeek 或其他供应商。**代价**：必须实现真正的认证/授权、租户请求 Ledger、客户端 ContextSnapshot 传输、重连与状态一致性测试；开发 PoC 与正式契约短期并存。

**风险**：客户端提供的本地摘要来源，服务端没有同步事实就不能独立证明引用真实性；只能做结构和人物范围约束，不能把它当用户鉴权或审计证据。提示注入、敏感历史外传、请求重放费用、跨租户音色等必须通过 #39/#43 安全测试。

## 阶段边界

- #38 只完成评审方案、接口契约和风险说明，不生产部署，不调用付费供应商。
- #39 在获得必要决策和外部条件后实现可测试的真实 provider 适配；Model/Cache/Token/费用和真实人物记忆质量均在该阶段验证。
- #42/#43 再正式接入音频、ASR、TTS 和音色，不以 #22 的 Android 模拟器证据替代 iOS 或真机验收。

## 回退

若新鉴权/人物服务范围存在重大问题，保留 Flutter 本地 #36/#47 的完整原始记录与导出，回退到离线 Mock，不能通过绕过认证或公开旧调试网关实现快速上线。
