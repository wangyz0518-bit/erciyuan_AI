# Qwen 与 CosyVoice 电脑端对比进展

> 状态：评审中
> 日期：2026-11-13
> 负责人：待团队分配
> 关联：D、[方案 PR #18](https://github.com/wangyz0518-bit/erciyuan_AI/pull/18)、[验证 PR #19](https://github.com/wangyz0518-bit/erciyuan_AI/pull/19)

## 当前结论

已完成一个角色、平静/开心/安慰/疑惑四表达的真实电脑端生成：Qwen、CosyVoice 3.5 Plus、Flash 各 32 条，共 96 条有效 WAV，并制作同文试听和混合盲听材料。两款云端均从同一中性参考创建音色，每款模型的四表达固定同一音色 ID。

复用连接后的首段 PCM 返回 P50/P95：Plus 为 **0.78/1.02 秒**，Flash 为 **0.68/0.86 秒**；本地 Qwen 当前整段返回入口为 **8.99/13.55 秒**。本机配置下，云端流式路线具备继续验证实时聊天的价值，当前 Qwen 配置不适合作为实时聊天默认后端。该结论不能外推为所有 Qwen 部署的性能上限。

**自然度、音色一致性、情绪辨识仍待人工盲听，尚未选定听感优胜者。** 建议把 Plus 留作质量候选、Flash 留作成本候选；如果盲听质量接近，再优先考虑本轮成本和延迟更低的 Flash。Plus 另有一条播放数据不足 60ms，需复核听感并调整缓冲后验证，不能只看首包时间宣布验收通过。

## 参考与测试设计

固定 Qwen3-TTS-12Hz-1.7B-CustomVoice 的 Serena，制作 10.96 秒中性合成参考。55 个汉字经本地 SenseVoice 转写核对，忽略标点无差异。参考 SHA-256：b5c8d7b1f0ccaa73d80ce9be757e47aed8464297c0877f2e1e6442d873fb5c8a。

Qwen 直接用 Serena；Plus、Flash 分别复刻同一中性 WAV。参考是合成音频，不是真人录音。预设与复刻路径不同，本试验比较本角色可用性，不作为通用模型排名。用户先前指出的 ZipVoice 自然度和跨表达一致性问题保留为历史结果，新路线直接生成最终台词。

台词来自 experiments/voice_poc/screening-cases.csv：8 句同文台词 × 4 表达，共 32 条；保留每条的首次成功输出，不挑选最佳生成。初始顺序种子 31、模型种子 21；四表达指令写入各轮 experiment.json。云端使用 PCM 24kHz 流式输出，输入为已准备完整的短句。本轮不含在线 LLM、ASR 或说话结束判定。

Flash 首轮成功 7 条后失败，随后一次补测在首条失败；用户检查开通后，剩余 25 条全部成功。补测仅包含缺失台词，重新排列顺序，保留原 7 条成功结果和 2 条失败记录。合并记录注明各原始目录、原始位置、原始 case 和原始 WAV，不覆盖原始日志。Flash 有 2 个成功会话的首次建连请求，均排除在热请求统计之外。

## 实测数据

Windows、i7-13620H、RTX 4060 Laptop 8GB、约 32GB 内存。Qwen 使用 qwen-tts 0.1.1、PyTorch 2.5.1+cu121、BF16、SDPA、6 个 CPU 线程；没有 FlashAttention 和 SoX，不将本配置当作优化上限。云端与本地按顺序执行，测时未并行运行 ASR 或其他模型测试。

| 项目 | Qwen 本地 | CosyVoice 3.5 Plus | CosyVoice 3.5 Flash |
| --- | --- | --- | --- |
| 成功音频 / 总尝试 | 32/32 | 32/32 | 32/34，含开通排障期间 2 次失败 |
| 四表达有效音频 | 每种 8 条 | 每种 8 条 | 每种 8 条 |
| 模型加载 | 7.20 秒 | 不适用本地加载口径 | 不适用本地加载口径 |
| 首次请求音频返回 | 11.84 秒 | 1.07 秒 | 1.01 秒；补测新连接 0.83 秒 |
| 热请求样本数 | 31 | 31 | 30，来自两段会话 |
| 热请求首段音频 P50 / P95 | 8.99 / 13.55 秒 | 0.78 / 1.02 秒 | 0.68 / 0.86 秒 |
| 热请求完整生成 P50 / P95 | 8.99 / 13.55 秒 | 1.38 / 2.05 秒 | 1.17 / 1.31 秒 |
| 设备首个非静音样本估计 P50 / P95 | 9.22 / 13.77 秒 | 1.26 / 1.53 秒 | 1.13 / 1.25 秒 |
| 热请求 RTF P50 / P95 | 3.59 / 3.80 | 0.40 / 0.57 | 0.37 / 0.46 |
| 播放数据不足填零 | 0 | 1 条，累计 0.06 秒 | 0 |
| PortAudio underflow | 0 | 0 | 0 |
| 自动转写字符差异 | 1/424 | 0/424 | 0/424 |
| 自然度 / 一致性 / 情绪辨识 | 人工待评 | 人工待评 | 人工待评 |

P50/P95 使用最近秩法；失败请求不进入成功延迟统计，失败数单列。两款云端运行时间、成功请求顺序并不完全相同，样本量只用于初筛，不构成服务等级保证，也不能据此断言 Flash 在所有网络/角色/长文本上更快。

Qwen 当前接口返回整段波形，首段音频时间与完整生成时间相同；不能与原生流式首包的机制混淆。RTF 大于 1 表示本配置生成速度慢于播放速度。完整生成时间小于音频时长的云端流式接口仍可能出现中途供给不足。

播放设备为系统默认的 **UU 远程虚拟音频 / MME**，24kHz 单声道，120ms 启播缓冲。DAC 时间戳只提供播放估计，未测远程耳边出声、实体扬声器或手机扬声器。Plus 的第 23 条、原始 case 30 在播放期间填零 60ms；PortAudio underflow 为 0 不代表应用没有缺数据。听感是否可察觉需人工核对；后续可比较稍大的缓冲与首声延迟权衡。

自动转写使用本地 SenseVoice，忽略标点；Qwen 的 1 个字符差异为“发”被识别成“挖”，可能来自合成或识别误差，不能当作正式人工字错率。自动转写不能验证情绪、自然度或说话人一致性。

## 云端用量、费用与排障

| 模型 | 成功请求服务端回报字符 | 按当前原价折算 |
| --- | --- | --- |
| Plus | 880，32 条均回报 | 0.1320 元 |
| Flash | 880，32 条均回报 | 0.0704 元 |
| 合计 | 1760 | **0.2024 元** |

按 2026-11-13 北京区 Plus 1.5 元/万计费字符、Flash 0.8 元/万计费字符折算，汉字计 2 字符、标点计 1 字符；复刻音色免费。[官方价格](https://help.aliyun.com/zh/model-studio/model-pricing)

这是服务端用量乘价目表的估算，**不是已核对的账单金额**，未抵扣免费额度。Flash 两次失败未回报 usage；如果把失败文本也按同价折算，总尝试文本预算估算为 0.20688 元，最终以控制台为准。本地 Qwen 没有云 API 调用费，电费和硬件成本未计。

实际处理过的问题：

1. DPAPI 文件末尾换行导致 Windows PowerShell 解密读取异常；读取时去除首尾空白，完整文件到子进程回归已通过。
2. 本机代理路径导致百炼 HTTPS/TLS 或连接超时；仅对当前子进程的官方百炼域名设置 NO_PROXY 后恢复，保留 TLS 校验，不改变系统代理。
3. Flash 首轮第 8 次失败的旧日志只有通用失败消息，未保留错误码，不能补推断其根因。增加脱敏错误码记录后，一次补测首条返回 AccessDenied.Unpurchased。用户检查开通后剩余 25 条成功。官方将该码归为服务开通/使用资格问题；不能由此认定最初 Key 无效或免费额度耗尽。[官方错误说明](https://help.aliyun.com/zh/model-studio/error-code)

脚本不自动重试；用户开通后发起的补测、最初失败均有独立记录。音色 ID 在创建后立即保存，本次连接排障没有重复创建音色。Key、业务空间及音色 ID、合成音频仅留在本机忽略目录。
