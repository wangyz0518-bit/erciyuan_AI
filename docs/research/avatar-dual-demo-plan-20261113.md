## 共同体验

两个独立入口或切换页面。全身构图，按钮为打招呼、换重心、暂停／继续、回待机。隐藏逐关节滑块。默认协调的呼吸与衣发变化，腿部重心动作可见，脚底不明显滑移。

三项候选动作 ID：idle（循环）、wave（挥手后回站姿）、weight_shift（腿部换重心后回站姿）。ID 为 Demo 语义约定，不隐式修改现有 Schema。动作需经过制作和验收，不把样例任意动作重命名为目标动作。

## Demo A：Live2D

所需：Flutter、Android 开发环境、既有 Cubism Native R5 组件；真实 MOC3、model3.json、纹理及动作。当前角色需通过分层、绑定与编辑器导出；官方样例可以先做接入演示，明确模型名与缺失能力。单图网格预览不能替代模型。

拟实施：
1. 盘点可用模型与三项动作，补齐缺失资源。
2. 新增独立预设动作入口及页面，复用 packages/live2d_avatar，保留旧调试入口。
3. 契约评审后新增 ZIP／manifest 加载、文件校验，适配现有 Android Java/C++ 读取本地文件。
4. 实现动作完成回待机、受控调度、暂停恢复与失败回退；检查自动呼吸、眨眼和动作曲线是否冲突。
5. Android 先演示；iOS 插件与真机另行完成。

预期涉及 apps/mobile_poc/lib 的新 Demo 页面、pubspec.yaml 及 packages/live2d_avatar 的读取适配。具体变更以实施时仓库为准。

## Demo B：视频动作

所需：Seedance 或制作方其他视频工具、媒体检查与转码工具（如 FFmpeg）、Flutter 视频播放组件；三段真实动作视频和封面。当前尚无合格三段视频，不把现有 App 录屏当 AI 视频素材。

建议首次统一为竖屏 720×1280、30 fps、MP4/H.264、无音轨、固定背景；此为待验证交付配置，不是生成工具输出承诺。片段以约 4–6 秒为制作目标，生成后可裁剪和转码并记录实际时长。统一参考角色、服装、光照、构图和基准站姿。

拟实施：
1. 制作、筛选三段视频，检查首尾、循环、手脚、衣物与身份。
2. 新增独立入口、视频页面和播放依赖。
3. 评审独立视频包格式后实现导入；候选信息包含动作文件、循环、起止姿势、允许切换点、结束去向和失败回退。
4. 准备下一片段，在允许点切换；动作中只保留一个最新待执行请求，避免任意中断与无界排队。
5. 测试解码开销、缓存上限、后台恢复和损坏文件回退。预加载方式由设备实测确定。
6. 完成 Android/iOS 对应验证。

首轮不做透明视频、任意镜头或精准口型。没有素材时只可交付明确标注的播放器框架，不算完整视觉 Demo。

## 包导入与交付

两类包共有角色标识、版本、封面和语义动作等候选信息，渲染载荷分开评审。导入需检查相对路径、越界解压、文件大小、缺失引用和格式版本；失败保留原可用包。

第二步到第三步完成条件：制作方交付包后，App 无需改代码或重装即可导入并执行三项动作。仅内置 assets 演示属于提前验证，不算完整链路完成。

每套交付可复现入口／安装包、资源取得方式、30–60 秒实际操作录像、运行指南、验收与成本表。大型媒体和受限 SDK／模型不直接提交 Git；交付时记录团队可访问的分发位置和使用范围。

## 共同验收（均为待测）

| 检查 | 操作 | 判定与记录 |
| --- | --- | --- |
| 待机循环 | 10 次 | 无明显跳姿、黑帧、脚滑 |
| 完整动作 | 挥手和换重心各 10 次 | 正确播放并回待机，腿部可见，无明显穿模或身份漂移 |
| 连续点击 | 快速交替 20 次 | UI 有反馈、调度符合规则，无无限排队 |
| 响应 | 记录按钮反馈和动作开始 | 初始目标 UI ≤100 ms、已加载动作开始 ≤1 s；超出需解释与评审 |
| 生命周期 | 前后台 5 次、重新进入 | 无崩溃、卡死、多重播放或旧角色残留 |
| 异常包 | 缺失、损坏、不兼容版本 | 明确提示及回退，原包保留 |
| 外部导入 | 制作方独立交付，导入并重启 | 无需改代码或重装，资源映射正确 |
| 稳定性 | 同设备连续 10 分钟 | 记录首帧、切换延迟、内存、卡顿与热感，不预填性能成绩 |
| 成本 | 记录全制作过程 | 人工工时、生成及重试次数、实际费用、包大小分开统计 |

优先同角色、同构图、同动作、同背景、同设备比较。若模型用官方样例而视频用当前角色，美术效果不可直接排名，只比较接入和交互。Android 模拟器、Android 真机、iOS 真机分开填结果；没有资源或设备写未验证／阻塞及原因。

## 初始依赖

- 已有：C 线 Android Live2D 接入与现成官方样例，尚在草稿 PR。
- 缺少：当前角色正式 Live2D 交付、三段合格 AI 动作视频。
- 待做：两类外部包导入、视频播放器调度、iOS Live2D 插件及双端真机验证。
- 待落实：负责人、生成账号和额度、测试设备、素材使用及团队分发范围。

完成后报告用户接受度、等待时间、制作成本、资源代价及双端稳定性；再评审首版路线。本文不设未经验证的工期或费用承诺。
