## 结论和证据

两条路线均具备实现基础，适合有限范围 Demo；尚不能认定任一路线已经满足全部产品要求。目标是自然待机和用户触发完整动作，先人工交付离线包验证第二步到第三步，不依赖完整生成服务器。

| 证据 | 支持的结论 | 不代表 |
| --- | --- | --- |
| Live2D 官方运行资源包括 MOC3、model3.json、纹理 [S1] | 有标准 SDK 运行格式 | 图片或大模型生成 JSON 即可变成模型 |
| SDK 提供动作、循环、淡入淡出和优先级机制 [S2] | 可建设预设动作调度 | 任意组合都不会穿模 |
| Seedance 支持图像、视频、音频和文本参考 [S3] | 可以尝试统一角色参考生成动作片段 | 跨片段身份、首尾姿态与循环接缝必然合格 |
| Flutter 支持本地、资源和网络视频，使用平台播放器 [S4] | 移动端播放有技术基础 | 无缝切换、透明视频和真机性能已经通过 |
| 现有 C 线 Android Live2D 代码与历史报告 [R1–R3] | 样例渲染接入有项目证据 | 龙角角色已有绑定或 iOS 已实现 |

工程复核基准：C 线提交 `daa7d12b83642ba09120207da800a6678b237b1e`，仍属草稿 PR #17，不代表 main 已合并。默认龙角角色是单图网格变形；官方模型通过 Android AssetManager 加载。外部 ZIP 导入和 manifest 解析尚未实现，依赖中尚无视频动作播放器。历史报告不是本轮重新验收。

## 方案 A：Live2D

制作流程：角色设计 → 分层和遮挡补画 → 网格／变形器／参数绑定 → 动作及物理制作 → 导出模型 → App 实时渲染。

优势：同一纹理与绑定保持人物外观；背景独立；可以组合受控呼吸、眨眼、动作及后续口部驱动。增加动作主要增加曲线，不一定重复储存整段画面。

限制：自定义角色需要真实分层、绑定和导出。当前没有自动生成合格绑定的验证。腿部、大转身和遮挡效果由原画与绑定范围决定；参数冲突仍会产生不自然变形。音量开合不是精准音素口型。当前需补外部包加载、调度及 iOS 适配；性能取决于模型和设备。

判断：基础接入可行且已有部分证据；当前角色制作质量、成本和完整包联调仍待验证。工具与素材分发条件按实际交付范围确认。

## 方案 B：AI 视频动作

制作流程：统一参考角色与站姿 → 分别生成片段 → 检查身份／衣服／手脚／背景 → 裁剪和统一编码 → 配置播放关系 → App 缓存、解码、播放及叠加界面。

优势：可以直接生成包含腿部和衣发的整体动作；符合点选完整动作的需求；素材一次制作后重复播放，不需每次点击生成。可由不同工具生产媒体。

限制：跨片段可能变脸、换饰品或站位漂移，需要筛选重做。循环与切换同时涉及画面匹配和解码准备；淡化可能出现双脸双腿，不能通用修复。固定视频不能任意改变视角或动作幅度，精准口型需额外流程。新增动作会增加媒体、下载和缓存开销，费用需包含重试与人工修整，不能断言更便宜。

首轮背景包含在视频中。任意背景替换需要抠像及透明播放方案，不能假设生成平台原生输出跨端透明视频。

判断：生成与播放有各自工具基础，适合验证有限动作；本项目尚未证实多片段连续体验达到要求。

## 同条件比较

| 维度 | Live2D | AI 视频动作 |
| --- | --- | --- |
| 自然待机 | 绑定与曲线决定，可持续驱动 | 片段内部表现潜力较好，重点是循环接缝 |
| 腿部完整动作 | 需要对应原画、绑定和动作 | 可以生成整体动作，需检查手脚和接续 |
| 身份一致性 | 同资产较可控，变形需验收 | 跨片段逐条核验 |
| 切换 | 参数过渡与冲突管理 | 姿势背景匹配与解码就绪 |
| 声音扩展 | 可继续建设口型驱动 | 精准口型需另做生成或混合处理 |
| 成本 | 分层、补画、绑定、动画工时 | 生成、重试、筛选、修整、媒体存储 |
| 工程复用 | Android 组件已有基础 | Flutter 页面可复用，播放器调度需新增 |
| 双端 | iOS 插件缺失 | 播放插件有基础，项目仍需真机验收 |
| 核心风险 | 制作效率、绑定质量 | 一致性、衔接、资源开销 |

这不是同角色实测排名。两者均不是自由三维模型，不能仅靠基础接入保证任意文本精准口型。先做[双 Demo](avatar-dual-demo-plan-20261113.md)再决定。
