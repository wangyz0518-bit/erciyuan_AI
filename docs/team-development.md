# 团队开发安排

本文将第一阶段详版 v2.0 的工作线与依赖关系转为多人协作安排。原 Word 文档中的单人交错执行顺序作为历史背景保留；团队可以在共同接口明确后并行推进，仍需满足联调依赖。

## 工作线边界

| 工作线 | 责任 | 第一阶段成果 | 负责人 |
| --- | --- | --- | --- |
| A 手机界面与交互 | 页面、输入、录音采集、播放、装配 C 的人物组件 | 手机文字聊天骨架及媒体操作，支持模拟和真实对话 | 待分配 |
| B 角色与对话核心 | 角色设定、性格、消息、记忆位置、对话 API、交流调度 | 固定角色真实对话，角色及消息保存与恢复 | 待分配 |
| C 形象制作与驱动 | 输入图片规范、表情素材、状态控制、展示组件 | 可复用素材包、独立预览器及可嵌入的展示组件 | 待分配 |
| D 声音处理 | 音色创建、文字转声音、录音转文字 | 可试听的真实音频、识别结果及独立测试入口 | 待分配 |

B 保存正式角色、消息及资源绑定；A 管理显示、操作和草稿；C/D 提供资源或处理结果。对话 API 由 B 接入，图片能力由 C 接入，声音能力由 D 接入。付费调用与密钥放在服务侧。

## 首批任务

以下均为待实施任务，没有自动建立 Issue 或指定成员。

| 任务 | 参与方 | 交付与完成条件 |
| --- | --- | --- |
| 确定分工与技术方案 | 全员 | 明确各线负责人、审阅伙伴、候选技术栈和试验额度 |
| 共同设计基线 | A/B 主导，C/D 参与 | 角色、会话、消息、请求、生成任务、人物状态及音频结果的接口约定 v1；成功、失败和取消样例 |
| 页面与角色原型 | A/B | 关键页面、角色档案和两套测试角色样例，核对输入输出 |
| 图片能力验证 | C | 按 v2.0 的样本目标验证素材与表情，记录适用条件、失败原因和实际效果 |
| 声音能力验证 | D | 验证自定义音色与短句合成，记录输入限制、耗时、用量和失败情况 |
| 手机骨架与对话核心 | A/B | A 先用模拟结果；B 接真实对话并保存记录；各自通过后连接 |
| 独立组件与联调 | A/B/C/D | 人物组件装配、声音测试入口、录音与播放片段；覆盖取消、失败和切换角色 |

设计基线通过后，C/D 能力验证与 A/B 原型可并行推进。真实文字聊天依赖 A/B 联调；完整语音交流属于下一阶段，不作为第一阶段已完成能力。

## 联调共同约定

- 请求使用统一标识，网络重传不重复保存或调用模型。
- 录音识别先形成可编辑草稿，由用户确认发送后进入对话。
- 取消后忽略迟到结果；切换角色停止旧音频，避免旧请求更新新角色。
- 文字成功而声音失败时保留文字；缺失表情回退为平静。
- 情绪与活动状态分别传递；说话状态不等于精确口型。
- 公共字段、错误格式及样例需要单独形成可审阅接口文件；本文不替代接口规格。

## 第一阶段验收

A 可在手机使用；B 能真实对话并恢复记录；C 有可用素材与可装配组件；D 有自定义音色及可用识别结果。保留各线演示、真机检查、用量与耗时、失败项及后续任务，明确真实与模拟能力的边界。

原计划中的测试数量、质量与成本均是目标或估算，须以实际验证更新。第一阶段以后再完成整轮语音联动、普通用户角色创建、基础记忆管理、账号隔离和用量控制。
